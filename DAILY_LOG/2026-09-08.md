# 日报 2026-09-08（AI 版）

## 用户报障修复：素材库点击无效 + 界面异常符号 + 画布空白（会话 2026-09-08-27）

用户在打包后的 .app（Tauri/WKWebView）中报告：左侧素材库卡片点击完全无效、界面出现"未知符号"（右下角/漂浮）、素材不高亮不进画布、控制台无报错。

### 根因（两个独立 bug 叠加，只读调查定位）

**Bug A 布局回归**（右栏被埋 + 滚动条 + 漂浮符号）：
- `SceneCanvas.tsx` 的 `<div className="canvas-host" style={{ position: 'relative' }}>` 内联样式覆盖了 CSS `.canvas-host { position: absolute; inset: 0 }`，host 从"绝对填充"退化为常规流块（高度=内容高度）。
- `RendererService.resize()` 用 `setSize(w, h, false)`——从不写 canvas 的 CSS 宽高 → WebGL 画布按**固有尺寸**（= 容器 × dpr）参与布局。Retina（dpr=2）下：画布 2 倍宽横向溢出盖住右栏背景；高度经 ResizeObserver 正反馈（150→300→600→…）指数膨胀 → 双向滚动条。
- 用户看到的"7 个未知符号（3+3+1）"= ParamPanel 位置 XYZ/旋转 XYZ/缩放共 7 个 number input 的步进箭头，因右栏背景被溢出画布盖住而"漂浮"在浅色画布上。
- 次要：顶栏按钮组（~1200px）在窄视口也撑破横向布局。

**Bug B 几何构建 Promise 永久挂起**（画布全空 + 点击"无效" + 无报错）：
- 打包后 WKWebView 以 `tauri://localhost` 自定义协议运行；`new Worker(new URL(...), { type: 'module' })` 的独立 chunk 需运行时二次 fetch，自定义协议下**静默加载失败（不触发 error 事件）**。
- `worker.ts` 的 build Promise 只在 message/error 事件时 settle → 永久 pending → 预设场景 6 组件 + 点击添加的组件全部无几何；`RendererService.requestBuild` 的 `.catch` 同步回退只在 reject 时触发，pending 时永不执行 → 无任何报错。
- dev 模式（http://localhost:5173）module worker 正常加载 → "只在打包后坏"的典型签名。

### 修复（4 层，均为防御纵深）

1. **布局**（`SceneCanvas.tsx` + `index.css`）：
   - 删除内联 `position: 'relative'`（CSS absolute inset:0 本来就是 AnnotationOverlay 的包含块）；
   - `.canvas-host canvas` 加 `width:100%; height:100%`——画布显示尺寸结构性钉死为容器尺寸（附带收益：导出时画布不再闪大）；
   - `.canvas` 加 `overflow:hidden`；`body` 加 `overflow:hidden`（全屏三栏应用，窗口级滚动条永远是 bug）；
   - 顶栏 `.topbar` 改 `flex-wrap: wrap` + `min-height: 46px`（窄窗口按钮组换行收纳）。
2. **Worker 加载根治**（`worker.ts`）：`defaultSpawn` 改 `import GeometryWorker from './geometryWorker?worker&inline'`——worker 以 data URL 内联进主包，零运行时 fetch，任何 origin（tauri://、file://）可用。dist 实测：无独立 worker chunk，构造为 `new Worker("data:text/javascript;charset=utf-8," + encodeURIComponent(...))`。
3. **Worker 挂起防御**（`worker.ts` + `geometryWorker.ts`）：spawn 后 4s 握手（geometryWorker 入口自报 `{ready:true}`；任何消息到达即视为就绪）；超时 → console.warn + 标记 dead + terminate，此后 build 直接主线程 `computeGeometry`（与子线程共用同一份逻辑，结果逐位一致）；error 事件同样置 dead（此后 postMessage 无人应答）。`GeometryEngine` 接口新增可选 `ready: Promise<boolean>`。
4. **IndexedDB 挂起防御**（`cache.ts`）：模块级 `dbReady()` 门（Dexie open 与 4s 超时竞速，超时/失败置 storageBroken，本会话直通 inner）；所有 Dexie 操作 try/catch 降级——缓存故障绝不污染构建结果（原实现 put 失败会连累整次 build reject）。
   - 预烘焙门控（`SceneCanvas.tsx`）：`inner.ready` 为 false 时跳过（避免打包应用里主线程同步跑 10 个管构建卡顿）。

### 教训（已记 D10）
- "部分功能正常"不能证明链路健康（本次：比例尺画对但投影链错的历史同款）；**无报错 + 无输出 = 优先怀疑 Promise 永久 pending**。
- 桌面端验收必须在**打包产物**（自定义协议 origin）里做，dev 模式（http origin）会掩盖 worker/存储类故障。
- 内联样式覆盖同名 CSS 是布局回归高发点；结构性防御（CSS 钉死尺寸 + overflow 裁剪）优于逐点修复。
